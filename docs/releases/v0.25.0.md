NexaRoute v0.25.0 is a proposed stable release after the v0.24.0 audit line. The draft
would include the NexaFlow workflow studio as a production-wired subsystem, a
provider-profile registry that makes "which dialects does this upstream speak"
a first-class, testable fact, multi-CLI compatibility for the four agent CLIs
that matter in practice, and a large body of correctness, security and
acceptance-harness work.

This release is **honest about what it does not claim**. The external
acceptance scopes tracked by issues #646–#652 require operator-owned
infrastructure (provider accounts, an organizational identity tenant, staging
Vault, live Kubernetes, a ComfyUI model host, and independent HA hosts). They
have not been accepted against real external systems for this draft. These are
**outstanding mandatory requirements, not exclusions**. Issue #653 additionally
requires exact-candidate coverage and the validated two-hour soak; issue #654
requires the final umbrella review. All nine issues #646–#654 must be closed
with `state_reason=completed` before v0.25.0 may be published. A fixture,
runner-local test, or merged code change does not replace external acceptance.

## Highlights

- **NexaFlow Studio is production-wired.** A durable, engine-agnostic workflow
  execution engine with a 23-node adapter registry, templates, a read-only
  editor canvas (palette, click-to-connect edges, node configuration, save,
  validate, publish, run) and admin APIs — reachable from the gateway, not only
  from tests.
- **Universal provider profile registry.** Provider capability is now data:
  a registry of profiles (auth mode, dialect, feature flags, media-path
  layout) with a published compatibility matrix, plus AgentRouter Messages and
  Chat profiles. Providers that do not match a profile keep the previous
  behaviour.
- **Multi-CLI compatibility.** Gemini `generateContent` ingress, and per-CLI
  proof for Claude Code, Codex, Gemini CLI and OpenCode, including stripping
  `?key=` from Gemini URLs in every path.
- **Read-only routing explainability.** A routing simulation that replays the
  exact candidate funnel and reports every exclusion reason, with
  alternative-profile comparison, without issuing any provider call.
- **Secret-safe diagnostics bundle.** `nexaroute diagnostics bundle` emits an
  allowlisted, double-scanned, `0600`-written JSON bundle that never contains a
  credential, prompt or response.
- **95% repository coverage is now an enforced gate**, not a target, and the
  soak harness validates its own evidence (commit binding, sustained seconds,
  every planned stage) instead of trusting a green badge.

## NexaFlow

- Durable workflow execution engine (phase 2) with per-run state, checkpoints
  and engine-agnostic node execution.
- Node adapter registry: 23 node kinds, 5 template-only (inert) nodes that are
  deliberately not executable yet.
- Studio surface: template gallery and use-template flow, `GET /templates/{id}`
  detail, `GET /nodes` schemas, editor canvas, palette/save/click-to-connect,
  node configuration panel, validate/publish/run.
- Production gateway wiring, including a security correction that restricts
  `gateway_base_url` to loopback addresses only.

## Providers and routing

- Provider profile registry plus the generated compatibility matrix;
  AgentRouter Messages and Chat profiles added.
- Gemini ingress through the canonical adapter, with regression coverage that
  `?key=` is always stripped.
- Idempotency-aware retry safety: retries are only issued when the request is
  provably safe to repeat — no exactly-once claim is made.
- Read-only routing explainability and alternative-profile comparison.
- Model quality regression gate: versioned suites, baseline comparison, and an
  offline CLI so a prompt-visible regression is detectable before a rollout.

## Security and secrets

- Vault Transit `nxs2` envelope-key support: per-secret data-encryption keys,
  the KEK stays in Vault, strict schema and key-version validation, bounded
  requests, classified redacted errors and **no local fallback**. Migration and
  rewrap commands write a verbatim backup and replace only after
  decrypt-verify.
- Gateway helper output bounded at 1 MiB; the Vault KV helper download cap is
  enforced during receipt, and helper HTTP status is verified rather than
  assumed.
- Admin cookies always carry `Secure`.
- OIDC callback-binding negative tests, and a supported live security snapshot
  through the admin endpoint.
- Loopback validation hardened against same-spelling variants, with a fuzz
  target and a release-gate regression suite.

## Correctness fixes

- Collision-resistant video job IDs, with duplicate-ID idempotency resolution.
- ComfyUI: reject case-insensitive duplicate output filenames; verify download
  checksums; fail closed on terminal replay; loud ledger read failures; and
  business rejections returned unwrapped from `Create`.
- Protocol: fail closed on unrepresentable content, failed Responses status and
  malformed error envelopes; drop whitespace-only system prompts (a fuzz
  crasher).
- Anthropic-to-OpenAI stream usage: cache tokens are carried through, and
  native SSE usage is parsed at the correct JSON level.
- TTS: truncated WAV payloads are rejected instead of being treated as audio.
- Browser/UI: routing-simulation toggles sized for the axe target-size rule and
  wrapped below 700px; the queue-full probe assertion no longer races the
  publish path.

## Quality gates and CI

- Coverage: repository-wide statement coverage is gated at **95.0%
  (inclusive, no package exclusions)** on every pull request and on `main`.
- Soak: the long soak produces `summary.json` and a validator fails closed
  unless the summary names the run's commit, contains every planned stage,
  reports the requested sustained duration, and carries a NOT_RUN block for
  live items.
- Manual runner acceptance workflows now exist for every external scope:
  Kubernetes (`k8s-live-acceptance`), Vault KV and Transit
  (`vault-runner-acceptance`), OIDC (`oidc-runner-acceptance`), HA
  (`ha-runner-acceptance`), an independent environment
  (`independent-environment`), and the live provider canary
  (`conformance-live-canary`). They are `workflow_dispatch`-only by design:
  they never spend real quota or touch a real cluster from a normal PR.
- Flake work: failover call-count assertions are attributed to the request
  under test (a marker-carrying upstream plus a deterministic attempt-ledger
  assertion), so a reused loopback port can no longer fail a correct gateway.

## Outstanding acceptance requirements — release blocked

The following scopes are **not excluded**. Each one remains mandatory for
v0.25.0. The relevant issue must remain open until the complete acceptance
criteria are met with genuine evidence.

- **#646 — Live LLM provider canaries.** Requires authorized provider accounts,
  exact endpoints and model IDs, explicit spending ceilings, and real tests
  covering authentication, streaming, tools, usage, errors, rate limits and
  failover. Contract and fixture tests alone do not satisfy this requirement.
- **#647 — Organizational OIDC.** Requires an authorized organizational
  identity tenant and test accounts, with real discovery, PKCE, JWKS rotation,
  claim/role mapping, negative cases, logout and audit evidence. Runner-local
  Keycloak is not organizational acceptance.
- **#648 — Production-like Vault KV.** Requires an authorized staging Vault,
  least-privilege policy, token lifecycle, rotation, outage/failover and
  recovery evidence. A disposable dev-mode Vault is insufficient.
- **#649 — Real Vault Transit.** Requires a genuine authorized Transit key,
  encryption/decryption round trips, tamper and invalid-ciphertext rejection,
  rotation, rewrap, rollback and fail-closed recovery evidence. Fake API tests
  are not live acceptance.
- **#650 — Live Kubernetes/Helm.** Requires a real disposable cluster and
  evidence for installation, upgrade, rollback, image consistency, readiness,
  termination, persistence, security and cleanup.
- **#651 — Real ComfyUI inference.** Requires an authorized ComfyUI server,
  compatible real model/workflow, successful inference, verified playable
  output and failure-path evidence. A fixture is not a generated video.
- **#652 — Independent multi-host HA.** Requires two independent hosts, shared
  PostgreSQL and Redis, a real load-balancing address, failure/recovery and
  backup/restore exercises, and measured RPO/RTO. Same-host containers do not
  satisfy this requirement.
- **#653 — Exact-candidate quality and soak.** Requires fresh inclusive Go
  coverage of at least 95% on the exact candidate, required stress evidence,
  and a validated sustained two-hour soak with all required stages and
  artifact provenance bound to that candidate.
- **#654 — Final acceptance umbrella.** Requires all preceding issues to be
  completed, all evidence reviewed, all mandatory gates passed, and a final
  release-readiness review. It must be closed last.

No issue may be closed as `not_planned` to bypass these requirements. The v0.25.0 gate requires `state=closed`, `state_reason=completed`, and current exact-candidate evidence metadata for every issue #646–#654. Independent review of the actual evidence remains mandatory. The generic exclusion mechanism remains available for other versions, subject to their policy.

## Upgrade notes

- No configuration file change is required. `v0.25.0` reads every `v0.24.0`
  configuration unchanged.
- New optional surfaces: NexaFlow admin APIs, the provider profile registry,
  the routing simulation, `nexaroute diagnostics`, `nexaroute comfyui-accept`
  and the Vault Transit `nxs2` key path. Each is opt-in; defaults are
  byte-for-byte the previous behaviour.
- Vault Transit mode fails closed. If you enable it, keep the previous
  configuration recoverable until `nexaroute secrets verify` succeeds against
  the new key.

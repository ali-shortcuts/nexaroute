# NexaRoute v0.23.0

NexaRoute v0.23.0 builds on v0.22.0 with a substantial round of provider-onboarding, routing, admin-UX, video-workflow, security, and operational-readiness work. The aim is to make routing decisions inspectable, compatibility claims evidence-backed, and load/recovery behavior repeatable. This release does **not** claim that every capability has been verified against every commercial upstream.

## Provider onboarding and protocol compatibility

- **Provider catalog and model provenance.** The Providers page consolidates presets, custom endpoints, bounded best-effort model discovery, manually defined models, and per-model test state. The `nexaroute provider-accept` command runs bounded discovery and generation probes and records whether a model is manual or discovered; it does not print resolved credentials.
- **Versioned conformance evidence.** A shared provider/protocol conformance manifest backs documentation, capability filtering, and the admin UI. Unsupported dimensions are excluded from routing when a request requires them, rather than silently dropped by an encoder. The opt-in `nexaroute conformance canary` exercises explicit scenarios under call/token/time/cost limits and reports partial evidence without automatically promoting unverified dimensions.
- **Protocol translation fixes and coverage.** Gemini generation-configuration repair and probes, Bedrock prompt-cache mapping, Responses tool-result/call fidelity, thinking round-trips, system-image handling, and streamed terminal-state behavior gained additional regression coverage. Cross-protocol support remains bounded by the documented field-level fidelity notes.
- **Cloud media addressing.** Azure OpenAI media routes use deployment-specific paths and API-version parameters where supported. Binary audio and multipart payloads preserve their documented bytes, while unsupported provider/media combinations fail explicitly rather than being sent to an invalid endpoint.

## Routing, decision policy, activity, and cost

- **Routing explainability and preview.** The router can expose stable, redacted exclusion reasons using the same candidate-eligibility funnel as real requests. The authenticated route-preview endpoint shows resolution, candidate ordering, exclusions, and the selected provider/model without issuing upstream calls or echoing session/selection keys.
- **Routing and coding-client workflows.** Virtual-endpoint session affinity, declared-capability workload profiles, first-route/connect wizards, bounded endpoint/auth/protocol testing, and request-history links make it clearer how a configured client maps to a real deployment. Codex and OpenCode connection flows are included alongside existing Claude Code onboarding.
- **Decision observability.** Decisions can carry a reproducible policy version and minimum-evidence threshold. Replay distinguishes policy-version mismatches, and opt-in shadow evaluation records alternative choices without changing served traffic or issuing additional inference calls. Classified failover causes and policy traces help explain observed behavior; learned policy changes are not silently adopted.
- **Live request activity.** The admin Activity view uses backend lifecycle events to show request attempts, outcomes, latency/TTFT, usage and cost basis, filters, and deep links. This is operational telemetry, not synthetic UI data.
- **Budget and cost correctness.** Virtual-key budget state exposes settled/reserved/remaining values and cost provenance; threshold-crossing webhooks are asynchronous, bounded, egress-guarded and deduplicated. Video jobs distinguish actual from estimated cost and retain explicit unknown states when reconciliation evidence is invalid.

## Admin UI and developer experience

- **Localization and accessibility.** English, Persian, and Pashto localization extends through the dictionary-based page-copy path, with RTL layout handling for Persian/Pashto. Shared design tokens and component primitives reduce style drift; contrast, asset-budget, API-handler wiring, and browser-flow checks protect the UI contract.
- **WebChat.** Conversation replies surface public-model, cache, and failover-attempt details from real response headers; failed replies can retry through the shared send path, Markdown export is supported, and image attachments are limited to routes that declare vision capability.
- **Video Studio.** The UI exposes job history, workflow steps, honest progress states, capability-gated creation, retry-safety assessments, cost caps, and output-integrity information.
- **Guarded video execution.** The opt-in `code-render` provider lets a configured text/coding model produce a validated declarative scene plan that a deterministic local FFmpeg renderer turns into an MP4. This is programmatic rendering, not native photorealistic video generation. The video pipeline also gains a bounded async-aggregator adapter, job leases, output-byte/hash checks, cost reconciliation, cancellation settlement, and terminal-job retention; those controls do not establish that a real external video model or ComfyUI installation has been exercised.

## Operations, security, and reliability

- **Measured performance work.** Reproducible benchmark/load profiles cover candidate pools of 10/100/1000 and document measured baselines and initial SLOs. The soak workflow records raw output, duration, resource samples and summaries; recent runs exercised sustained local traffic, recovery, race detection, and budget-leak slope. These results are controlled-run evidence, not production-traffic SLOs.
- **Resilience and state-store hardening.** Failure-injection and race-sensitive regression coverage was expanded. Follow-up hardening improves backup/restore validation and journal recovery, cross-process storage semantics, egress restrictions, OIDC rate limiting, and resource-leak checks. PostgreSQL/Redis and container/deployment workflows are tested in CI against disposable services; this does not substitute for proving a customer deployment's topology.
- **Release provenance.** The canonical release workflow runs the full verification suite and reachable Go vulnerability gate, builds Linux amd64/arm64 gateway and video binaries, generates and validates an SPDX SBOM, checksums every required artifact, exercises installer/runtime smoke tests, checks embedded versions, and signs the checksum manifest with keyless Sigstore OIDC. Publication is gated on this workflow succeeding for the exact tag.

## Fixes and regression coverage since v0.22.0

- Fixed the provider preset category-filter handler and made first-run browser assertions deterministic while presets load.
- Fixed unknown-model fallback so the router's per-attempt eligibility re-check honors `fallback_on_unknown_model`; requests reach the configured fallback deployment instead of synthesizing a false `no usable deployment` error. Regression tests cover fallback enabled/disabled, media requests, and truthful protocol-mapping errors when no upstream attempt is possible.
- Fixed Gemini alias repair so an unsupported token-budget field cannot be reintroduced.
- Made zero-valued Go soak durations such as `0s` disable the sustained phase as documented, while malformed and negative durations still fail closed.
- Pinned race-soak to a bounded duration so an operator-requested long soak cannot make the race stage exceed its own test timeout.
- Improved release SBOM validation to reject unpinned Go modules and mismatched Go-module PURLs without requiring test-only modules that are not linked into shipped binaries to appear in the SBOM.

## Verification boundaries and upgrade notes

The provider-acceptance and conformance-canary runs recorded during this release used a controlled loopback upstream, not commercial provider tenants. They prove the production command/code paths against the local contract fixture; they do not claim LIVE-VERIFIED compatibility with a real provider. Live external OIDC-provider, Vault/keyring-daemon, Kubernetes-cluster, and real ComfyUI/video-model interoperability remain deployment-dependent and unverified until the procedures in [External verification](../EXTERNAL_VERIFICATION.md) are run and recorded. See [Known gaps](../KNOWN_GAPS.md) for the full boundaries.

No additional breaking configuration change is introduced specifically by v0.23.0. Plain HTTP provider URLs remain restricted to explicitly spelled loopback hosts; use HTTPS for remote upstreams. Back up configuration and state before upgrades, and follow [Installation](../INSTALLATION.md) and [Release verification](../RELEASE_VERIFICATION.md).

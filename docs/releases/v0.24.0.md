# NexaRoute v0.24.0

NexaRoute v0.24.0 is the audited, hardened successor to v0.23.0. It is the product of the post-release quality and architecture audit (#593) and the remaining-work mission that followed it: every confirmed defect the audits produced is fixed with regression coverage, the static-analysis battery was driven to zero or to an explicit checked-in baseline, the video subsystem's state planes became durable on PostgreSQL, and the program's open architecture questions were settled by recorded decisions (ADR 0001–0006) instead of remaining implicit. This release does **not** claim that every capability has been verified against every commercial upstream; the verification boundaries at the end of these notes are part of the release contract.

## Confirmed-defect fixes (post-release audit #593)

- **Leased video job could never run after a restart.** A video job whose lease was held by a process that restarted could be stranded permanently; the lease/recovery path now makes such jobs runnable again, with regression coverage.
- **Create idempotency check-then-act race.** Two concurrent creates with the same idempotency key could both pass the existence check; the create path is now atomic, with a race regression test whose assertions demonstrably execute.
- **Configuration scope was overstated.** The deployment report and `/api/hello` previously implied configuration snapshots were shared through the control plane. Configuration is, and always was, loaded from and saved to the local file per replica; the report now says `per-instance`, a regression test pins the contract, and the HA documentation set is kept mutually consistent by a checked script (`scripts/check-ha-docs.sh` in `verify.sh`).
- **Trusted-proxy handling** was completed and hardened as its own audited slice, alongside the audit's security and permissions findings (each reproduced red-then-green before its fix was accepted).

## Architecture slices and hardening (audit tail)

- **Shared circuit-breaker state store** (`internal/sharedstate`, ADR 0002): a versioned, revision-CAS breaker document (cooldown/retired markers only) with monotonic merge, clock clamping, malformed-document rejection and an outage contract of "keep local truth" — no fallback ever opens circuits. Real PostgreSQL and Redis adapter tests cover concurrent writers and restart persistence.
- **Analysis triage to zero or baseline:** the gosec G204 command-execution findings, G304 file-path findings, G703/G704 egress findings and the staticcheck backlog were each triaged at source with recorded dispositions; a multiplicative size-arithmetic defect in the redaction path was removed.
- **Config validation** gained a documented phase-1 structural slice, and the virtual-keys service a phase-1 extraction — both behavior-preserving and evidence-recorded.
- The **unimplemented adaptive routing strategy** stub was removed rather than left as a selectable no-op.
- The **OIDC nonce limitation** is now stated explicitly in the acceptance documentation instead of being implicit.

## Video durability (PostgreSQL)

- **Durable job store** (#609): video jobs, checkpoints, idempotency and lease claims are PostgreSQL-backed — atomic across processes and restart-safe — selected by the same backend configuration as the rest of the control plane, with the file store remaining the zero-service default.
- **Durable cost ledger**: reservations and settlements are persisted with exactly-once settlement semantics — a duplicate settlement charges once, a conflicting actual is an error, aggregates are computed from rows (restart-proof), and a store failure is loud rather than a silent fallback to volatile accounting. Runtime wiring follows the job-store backend and fails startup rather than degrading silently.
- **Asset read integrity:** local asset reads now verify the recorded size and SHA-256 written at `Put` time; corruption or truncation fails the read. Legacy records without checksums still read as before.
- Positioning is explicit and settled (ADR 0004): video is a **single-active-process** subsystem. The PostgreSQL stores are durability features; rendered/input assets remain host-local, so multi-replica video is not a supported topology in this release.

## Cross-replica breaker sync (opt-in)

- With a shared control-plane backend, replicas can now converge on provider incidents: a background syncer (never on the request path) publishes local cooldown/retired markers and applies remote ones. Application is deliberately conservative — a remote marker can only extend a local cooldown, never shorten one, never overrides a local retirement, and a remote `retired` is honored only as a bounded 30-minute cooldown. A shared-store outage aborts the round with local state untouched, degrading the fleet to exactly the previous per-instance behavior. Accepted semantics are recorded in ADR 0003, including the decisions that sync stays **opt-in** (default off, byte-for-byte previous behavior) and that the 10-second default cadence stands.
- The deployment report derives and exposes the breaker scope (`per-instance`, `shared-host`, or `shared`) from the same configuration, with warnings for combinations that cannot cross processes.

## Quality gates (ADR 0006 ratchet)

- **golangci-lint 69 → 0** with the pinned v2.15.0 configuration run uncapped — the audit report's display cap had been hiding same-text findings; triage now always runs with the caps disabled and a clean cache. No lint rule was disabled to get to zero (one scoped, documented test-only exclusion). **staticcheck 0**, **deadcode 0** (the last four unreachable functions removed after caller verification).
- The audit workflow is now a **ratchet**, not just a report: golangci-lint, staticcheck and deadcode fail on any finding; coverage fails below **85%** (this release measures 85.1% on the final audit run; the coverage job now installs ffmpeg, fixing a ruler defect that had the render suite silently skipping); gosec fails on any finding outside a checked-in baseline.
- **gosec correction:** the long-cited CI figure of "53 findings, all G304" was produced by a silently incomplete analysis — gosec v2.29.0's bundled x/tools cannot decode the CI toolchain's export data, so its SSA/taint rules (G703/G704) reported nothing in CI (the artifacts' own package-loading errors named the failure). A working analysis finds **87** findings (53 G304 + 30 G703 + 4 G704); all were re-triaged at source for this release as operator-controlled boundary operations (CLI flags, environment variables, config values, constant bundle entry names, the operator-run videogen client), with zero confirmed defects. The baseline encodes all 87, the gosec job pins a compatible Go version, and the baseline checker fails loudly if an analysis is ever incomplete again.
- **Autopilot kept — and now directly tested** (ADR 0005): the routing-policy canary controller's five public methods that had no direct package-level coverage (`TargetPolicyID`, `TargetMatches`, `Release`, `Evaluate`, `Rollback`) are covered at 100%, pinning lease-release, gate-evaluation-without-mutation, and rollback-restoration semantics. The feature is documented as supported in `docs/CONFIGURATION.md`.

## Decisions recorded (ADR 0001–0006)

- **ADR 0001:** local configuration stays authoritative; cross-replica config propagation is not a product requirement and no shared-config implementation is approved.
- **ADR 0002/0003:** breaker state-store contract and its opt-in production wiring, with the policy answers above.
- **ADR 0004:** video stays single-process positioning (see above).
- **ADR 0005:** autopilot kept and tested (see above).
- **ADR 0006:** audit ratchet gating (see above).

## External acceptance executed for this release

Bounded, credential-free acceptance was actually run against real external surfaces: a real IdP's OIDC discovery and JWKS endpoints pass through the project's harness; a non-OIDC issuer is correctly rejected; the Vault helper and OS keyring paths fail closed when absent; the command key-provider protocol and the secrets rotate → encrypt → verify → decrypt round-trip pass; a wrong key fails closed. Backup/restore/doctor drills pass end-to-end, including corrupted-bundle and wrong-key refusals. The Docker image is distroless and non-root, and the Helm chart ships hardened defaults (non-root, read-only root filesystem, dropped capabilities, seccomp).

## Verification boundaries and upgrade notes

Live tenant OIDC login, a real Vault or OS-keyring round-trip, live commercial provider probes (zero paid calls were made), a live Kubernetes install, real OTLP collector ingestion, and live Azure/Vertex/Bedrock tenants remain **unverified** — they need operator credentials and environments, and nothing in this release claims them. Production multi-hour soak/SLO evidence and live multi-host HA behavior are likewise deployment-specific and not claimed. See [Known gaps](../KNOWN_GAPS.md) and [External verification](../EXTERNAL_VERIFICATION.md) for the precise boundaries and the procedures to close them.

No breaking configuration changes are introduced by v0.24.0. All new behavior is opt-in with defaults that preserve v0.23.0 behavior (breaker sync off; PostgreSQL video stores only when the PostgreSQL backend is configured). Back up configuration and state before upgrading, and follow [Installation](../INSTALLATION.md) and [Release verification](../RELEASE_VERIFICATION.md). The v0.23.0 tag and its assets are unchanged.

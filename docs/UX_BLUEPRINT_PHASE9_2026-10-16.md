## 3. Proposed information architecture and nav tree

Principles (from matrix): credential vault → connection → model/deployment → saved route → consumer/agent connection → attempt trace. Progressive disclosure: simple path first, advanced behind explicit expanders. No raw JSON on default surfaces.

```
Overview            system at a glance; setup rail; health by layer; recent signals
Providers           preset/custom onboarding wizard; connection list; per-connection detail
  └ Connection detail   credential ref · discovered models · capability evidence · tests · health
Routing             simple builder: 1 primary + ordered fallbacks + failure-policy summary + test
  └ Route detail        resolved execution · version/diff · attempts · linked activity
Activity            requests ledger (grouped: request → attempts) + aggregate usage tab
Playground          bounded manual request + trace (unchanged)
Connect  (NEW)      per-agent setup: Claude Code · Codex CLI · OpenCode — route/key/snippet/verify
Video Studio        brief → job → asset; failures/retries/cost (see §4)
Access              virtual keys / teams / projects (canonical; Settings links here)
Policies            posture + simulator (lifecycle stays in CLI, deep-linked)
System              Settings (slim) · Audit · Budgets & Cost · Evals · Observability
```

Concretely: keep 13 sidebar items working (no breakage), but regroup visually into **Operate** (Overview, Providers, Routing, Activity, Video Studio), **Use** (Playground, Connect), **Govern** (Access, Policies, Budgets & Cost, Audit, Evals, Observability, Settings). The only new destination is **Connect**; everything else is re-homing existing cards. Whether Connect ships as a page or a modal flow is uncertain — requires validation (prototype both against #415).

## 4. Wireframe descriptions (layout-agnostic, no competitor branding copied)

- **Overview** (verified as built; keep): hero with 3 CTAs → 4 metric cards (gateway requests, healthy deployments, public routes, privacy-safe events) → setup rail (3 steps with done/current states) → health-by-layer (gateway / providers / routes / client access, each with next action) → topology + recent signals. No change recommended except deep-linking each layer to its page (already mostly true).
- **Providers**: list (search, status pill per connection: Draft / Untested / Testing / Ready / Degraded / Disabled / Stale) → connection detail with 5 tabs: Identity (name, scope, protocol, base URL), Credential (named vault ref, rotation state — never the secret), Models (discovered + manual add, capability flags, freshness timestamp), Tests (bounded test picker with cost/quota notice + result evidence), Health (passive signal, window + denominator). Wizard = same 5 steps in sequence for first-run.
- **Model/Route detail**: header (public name, active version, status) → Resolved execution panel (primary → retry rule → credential selection → fallback order → final error behavior, as one ordered list) → Test this route (bounded, shows attempt waterfall) → Versions (change note, diff, rollback) → Linked activity (prefiltered). Advanced (conditions, transforms, weights, expressions) behind an "Advanced policy" expander with dry-run.
- **Live Activity**: two tabs — Requests (server-paginated ledger; filters: time, route, requested vs resolved model, key, status/error class, request ID exact match with `id:` prefix; grouped view toggle collapsing attempts under the request, URL-persisted) and Usage (aggregates: counts, success rate, p50/p95 latency, tokens, estimated cost labelled ESTIMATE). Row → detail drawer: request ID/time, requested route/version, attempt waterfall (target, credential label, timing, error class, rotation event), redaction state, next diagnostic action (link to route/provider, safe replay via Playground prefill). Never claim sub-second "real-time": label stream state (Connected/Reconnecting/Buffered, last seq).
- **Settings (slimmed)**: Connection (base URL), Routing defaults (strategy, affinity, failover, probe), Client access state, Lifecycle (drain, revision/rollback), Privacy defaults (content capture OFF, retention, sampling — each opt-in with new-data-only note). Consumer keys, identities, profile privacy become cross-links to Access / Cost. Every item shows source badge (console-managed vs declarative) and effective precedence — NexaRoute-specific recommendation; exact badge taxonomy uncertain, validate against the config source/history surface (`/config/history` in §2).
- **Video Studio** (keep structure; harden states): brief composer → queue (Queued / Admitted / Planning / Submitted / Processing / Polling / Uploading / Composing with progress) → asset (preview, download, provenance: prompt hash, provider, model, cost estimate) → failure card (error class, retryable? yes/no, Retry with same brief, Edit & resubmit). Poll only while active (already true); add explicit expired-asset and provider-unavailable states, labelled SOURCE-ONLY until exercised against a real provider (no behaviour inferred from the fake provider).

## 5. Default vs Advanced field inventory

Rule: a control is on the **default** surface only if a first-time operator needs it to complete the page's primary job (add a provider, create a working route, see what is running, spend nothing by accident). Everything else moves behind an **Advanced** expander, an object-owned detail screen, or a deep link — it is moved, never deleted. Raw JSON is never a default surface.

| Surface | Stays on default | Moves to Advanced / detail |
|---|---|---|
| Providers (add/edit) | preset picker, display name, base URL, credential vault reference (write-only), **Test connection** | custom model-discovery paths (`listPath`/`idPath`-style parsing), proxy/header overrides, per-model capability overrides, timeout/retry numerics |
| Routing (simple builder) | public name, one primary deployment, ordered fallback list, failure-policy summary in one sentence, **Test route** | `candidate_pools`, `route_profiles`, `virtual_endpoints`, `fallback_chains` raw objects (today rendered as a raw-JSON `<details>` dump — the clearest clutter instance in §2), scoring weights, capability expressions, hedging/Retry-After numerics |
| Route detail | resolved execution order, active version, linked activity | version diff internals, dry-run request attributes, per-policy expressions |
| Activity | request ledger, status/route/model filters, request-ID lookup, attempt waterfall in the drawer | content capture (opt-in, off by default), sampling/retention controls, raw event payload |
| Settings | connection base URL, routing defaults chosen from human-readable presets, client-access state, privacy defaults (capture OFF, retention) | drain/rollback internals, probe schedules, numeric routing strategy weights, consumer keys and identities (deep links to Access / Budgets & Cost — today duplicated here, §2) |
| Video Studio | brief, capability-supported inputs only, job state, cost estimate labelled ESTIMATE | per-shot provider parameters, seeds/reference plumbing, composition internals |
| Playground / WebChat | conversation, route picker, per-reply resolved-route badge | temperature/token/system-prompt numerics behind one Advanced toggle |

## 6. Accessibility, keyboard, responsive and privacy acceptance criteria

These are NexaRoute requirements to be tested (matrix row 11: no competitor publishes a complete contract to copy).

- **Keyboard:** every primary job in §5 completes keyboard-only; visible focus on all interactive elements; command palette (existing ⌘K / Alt+1…n) reaches every destination in the §3 tree; drawers/expanders trap and return focus correctly; no keyboard traps in the attempt waterfall or video queue.
- **Live regions:** stream state changes (Connected / Reconnecting / Buffered) and request completion are announced via a polite live region; token-level streaming is never announced per token.
- **Contrast & themes:** text and status colours meet WCAG AA in both light and dark themes; health/degradation is never carried by colour alone (icon + text label on every status pill).
- **Responsive:** the §3 destinations remain fully operable at 390×844 (the phone evidence size in this document): ledger and waterfall collapse to a single column, tables become cards, no horizontal scrolling for primary actions.
- **i18n/RTL:** EN/FA/PS body copy through the existing dictionary seam; RTL mirrors navigation and route chains without breaking the attempt order semantics (attempt order is always labelled numerically).
- **Privacy:** request/response content capture is OFF by default everywhere (§1 rows 6–7); enabling it is an explicit per-surface opt-in that states what will be stored and for how long; logs are metadata-first with retention controls and independent error/spend switches; secrets are write-only and never rendered back, including in traces, screenshots and exports.
- **Honesty states:** empty, loading, error, stale and disconnected states exist for every live surface and are visually distinct; stale data is never presented as live (§1 row 6, §4 Live Activity).

## 7. Staged implementation plan

Sequenced; each stage is its own issue and its own PR — this blueprint authorises none of them by itself.

1. **Stage A — Information architecture:** #411 (simplify navigation, settings and progressive disclosure) implements the §3 tree and the §5 inventory moves; #416 (design system and visual polish) supplies the shared tokens/components both stages render with.
2. **Stage B — Live truth:** #410 (live routing activity, request waterfall, real-time dashboard) implements the §4 Live Activity contract on the existing SSE stream; #413 (frontend/backend contracts and browser E2E) locks every §4 surface to a real backend contract so the UI cannot drift from the data plane again.
3. **Stage C — Routing brain:** #412 (adaptive routing policy engine) consumes the route-detail and dry-run surfaces specified in §4; the task-intelligence phase builds classification on top of it.
4. **Stage D — Creation surfaces:** #414 (Video Studio workflow UX) implements the §4 Video Studio states; #415 (coding agent profiles) implements the **Connect** surface from §3 (page vs modal decided by its prototype, §3); the WebChat phase turns Playground into the chat client with the per-reply route badge from §5.
5. **Stage E — Safety of the new brain:** the autopilot-safety phase (policy canary, automatic rollback, resilience game-days) gates every adaptive behaviour Stages C–D introduce, before any of it can act on live traffic by default.

### The only genuine gaps found (all in the callback binding gate)

The callback handler checks the flow-binding cookie *before*
`takeState` deletes the one-time transaction, and checks the HTTP
method before either. No existing test exercised those branches:

1. Callback with **no flow cookie** (binding absent).
2. Callback with a **malformed flow cookie** (present, not a
   32-byte binding).
3. Callback with the **wrong HTTP method** (POST to the GET-only
   callback).
4. **Provider-error callback state consumption** (the error path
   takes the state before the error check; replay was only pinned
   for the success path).
5. **Login-start audit failure** (`authLogin` records
   `auth.login.started` after `Begin`; a failing audit write must
   fail closed with no redirect and no flow cookie).

## 6. Provider-specific claims and clock-skew limits (from code, not from a live tenant)

These are implementation facts an operator must know before
interpreting live results; they are not live observations:

- Role claim: top-level only. The claim named by `role_claim` must
  be a string or an array of strings; anything else (including a
  nested object such as a provider's nested group claim) is denied
  as a malformed role claim. A provider whose groups live in a
  nested claim needs a provider-side mapper to a top-level claim.
  This is a documented limitation, not a defect demonstrated in
  this recheck, and no behavior was changed for it.
- Clock: expiry is enforced with zero leeway and no custom clock;
  `nbf`, when present, is enforced with a 5-minute leeway
  (go-oidc v3.15.0 library behavior, pinned by
  `TestOIDCReviewClockClaimsPinned`); `iat` is not independently
  checked. The operator records the observed clock offset on a live
  run; the gateway has no tolerance to configure.
- Audience: the expected audience must be present in `aud`;
  `azp`, when present, must name this client exactly; a token
  without `azp` is allowed.
- JWKS: the current JWKS document is fetched on every callback, so
  a retired key stops verifying immediately; a JWKS outage fails
  the callback closed.

## 1. Result

The six core surfaces named in the issue were simplified without removing any page, route, API, or control:

| Surface | Before | After |
|---|---|---|
| Global nav | 13 flat sidebar items | 13 items grouped under three labels — **Operate** (overview/providers/routing/video/activity), **Use** (playground), **Govern** (policies/access/audit/cost/evals/observability/settings). Labels collapse away in the icon rail and bottom bar. |
| Overview | 4 inert `metric-card` tiles | The same 4 cards are now navigable buttons deep-linking to Activity / Observability / Routing. |
| Provider edit | Auth mode, max-concurrency, credential-pool editor, header/proxy summary all inline | Those four rare controls move behind one `Advanced` disclosure; primary flow (name, base URL, protocol, credential + clear, data handling, models) stays visible. |
| Routing | Advanced objects summary hard-coded, one throwaway label | Advanced disclosure now routes through `bt()` copy explaining it is read-only/backend-owned. |
| Settings | One page, 7 cards, duplicated Consumer-keys and Identities tables | Five tabs — **Gateway · Routing · Security · Data · Expert**. Duplicated key/identity tables become deep links to the canonical Access and Cost pages; rare routing/probe numerics move under per-card `Advanced` disclosures. |
| All | — | Progressive disclosure is achieved with native `<details>` and an ARIA tablist; no new navigation state on the server. |

The two rare routing numerics and two probe numerics are now **read by `save-settings`** (previously only "preserved"), closing the dead-control class tracked by `TestSettingsControlsContract`.

### Browser + axe evidence

- `docs/browser-evidence/phase11-ia/manifest.json` — `generated_at 2026-10-18T02:40:25Z`, 104 screenshots (13 pages × 8 theme/language/viewport combos), SHA-256 per shot.
- A separate capture of the unmodified `HEAD` UI (into a temporary dir, then removed) was compared page-by-page against the manifest `axe` map. After the fix described below, the only difference is **light/settings: 17 → 16** serious contrast nodes. No page gained a serious/critical violation.
- The remaining serious `color-contrast` nodes are **pre-existing** on every light-theme page (the desktop sidebar stays dark in light theme) and are outside #411; they are neither introduced nor hidden here.

**Defect found and fixed during verification:** the new `.nav-group` labels initially inherited `--subtle`, which fails contrast on the (hard-coded dark) sidebar in light theme and added 3 serious `color-contrast` nodes per page. The labels now use a sidebar-appropriate fixed color (`#8fa1b8`), restoring the baseline violation count (and improving Settings by one).

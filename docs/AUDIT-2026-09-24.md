# NexaRoute beta audit — 24 September 2026

Baseline: `9a40d0df5ad8c2d4b26d221980e9d11d5beb4cb4`.
Initial deliverable version: `0.6.1-beta.1` on `fix/beta-compatibility-install`.

## Verdict

The gateway is buildable and locally usable, and already has substantial
single-process routing/recovery functionality. It was **not bug-free**: the
baseline test suite passed while new regression tests reproduced protocol and
resource-management failures. This beta addresses the findings below, rather
than asserting complete compatibility or superiority over established gateways.

## Findings and changes

| Area | Defect / consequence | Beta change |
| --- | --- | --- |
| Release automation | Only `v0.3` triggered releases; artifact/version assertions were stale | `v*` workflow, tag/version check, prerelease flag, reusable packaging script |
| Version reporting | CLI 0.6.0 vs API 0.5.2 | Shared buildinfo version and actual protocol inventory |
| Installation | Linux binary selection on other OSes; copying over a running binary | OS/architecture validation, atomic replacement, checksum downloader, source install option |
| Responses admission | `/v1/responses` bypassed global admission control | Included in the same bounded data-plane admission path |
| Responses dispatch | Canonical Gemini/custom Responses path was ignored, including repaired retries | Initial/repaired requests use the actual bundle path |
| Endpoint joining | Gemini base ending `/v1beta` could duplicate the API prefix | Normalize version prefix; escape model-in-path identifiers |
| Streams | Canonical body was not closed | Close on success, cancellation, parse failure and client-write failure |
| Streams | Trailing usage overwrote remembered completion | Latch completion, retain final usage, stop on explicit terminal markers |
| Gemini streams | Every partial content chunk was treated as complete | Require explicit finishReason or blocked-prompt terminal feedback |
| Responses tool streams | Parallel calls all used index zero; final output/arguments disappeared | Preserve upstream indices; allocate distinct output items; emit complete done/final objects |
| Stream failures | Failed/truncated response also emitted a successful tail | Single failure outcome, no fabricated successful completion |
| Precommit failover | Canonical emitters committed before validating the first frame | Lazy emitter creation allows failover on an invalid first frame |
| Usage | Canonical streaming token reports never reached the tracker | One cumulative usage callback per response; input/output counts retained separately |
| Responses routing | Context/cost fields and quota estimate overlay missing | Fill the same estimates/reservations; do not consume attempts for skipped candidates |
| Responses health | Some transport/committed-stream failures lacked health updates | Align with deployment/provider and streaming-scope failure handling |
| Conversation semantics | Previous response ID and hosted tools silently discarded | Explicit 400 for unsupported state, stored responses and non-function hosted tools |
| Thinking | Gemini thought text received a fake Anthropic signature | No fabricated signature; unsigned foreign stream thinking is not emitted to Anthropic |
| Response validation | Empty/malformed canonical objects could become apparent success | Validate Chat/Messages; reject missing Responses output and empty Gemini envelopes |
| Capability reload | Operator capability/endpoint changes could retain stale contracts | Include provider configuration identity when invalidating capability evidence |
| Dashboard editing | Advanced model pricing/context and provider fields dropped on save; new protocols missing | Preserve existing fields; expose Responses/Gemini and Gemini auth mode |
| Documentation | 0.3/0.5/0.6 claims contradicted actual code | Current installation, endpoint table, compatibility and operational boundaries |

Final Responses SSE objects retain output with explicit bounds: 8 MiB text/arguments
and at most 4096 items (a limit breach errors the stream). This is an intentional
resource limit, not unlimited output support.

## Comparison with established gateways

This is a capability comparison based on source/docs, **not** a throughput or
reliability benchmark. No numeric superiority claim is justified.

| Dimension | NexaRoute beta | Broader gateway ecosystem |
| --- | --- | --- |
| Distribution | One Go binary, embedded UI, no runtime database requirement | Varies by product and deployment mode |
| Routing | Health leases, P2C pressure, affinity, priority, advisory quota/cost, failover | LiteLLM documents routing strategies, cooldown/fallback and key/team routing; Bifrost documents provider/governance/key routing |
| Provider protocols | Four upstream families, three ingress families with bounded translation | LiteLLM documents 100+ provider integrations; Bifrost has a broader provider/governance ecosystem |
| Multi-node/HA | Single-process in-memory state | Production products offer additional distributed infrastructure/features; edition matters |
| Governance | Static client keys, RPM limit, local/admin-key control | Full key/team lifecycle, budgets, enterprise policy require additional implementation here |
| Stateful APIs | Stateless Responses subset | Full stateful provider features are not synthesized by this gateway |
| Model quality | Operator priorities/capabilities | No benchmarked semantic/learned quality router was added |

## Remaining priorities

1. Test exact provider/model and client combinations with real credentials.
   A successful model discovery or one-token probe is not proof of tool/vision/
   reasoning compatibility.
2. Add explicitly evaluated Responses caching/hedging and broader request-field
   conformance; avoid expanding advertised compatibility before tests exist.
3. For public multi-user deployment: secret vault, key lifecycle, hard budgets,
   TLS/reverse proxy, role-based administration and durable audit/usage storage.
4. For multi-replica operation: shared quota/affinity/breaker state and a measured
   rollout plan. Current process-local counters do not enforce global limits.
5. Measure realistic request/stream workloads before tuning for speed or claiming
   to outperform another gateway.

A provider that is down, has an invalid key, or forbids a capability cannot be
made functional by gateway intelligence. Correct behavior is bounded retry,
accurate diagnostics, recovery testing and failover to an eligible provider.


## Second review — 0.6.1-beta.2

Review baseline: `2e7d3697f0c9334518e32b3b57e5c7353f460986` (beta.1).
The second pass found additional defects, including in the preceding changes.
A passing first review did not establish absence of bugs.

| Finding | Reproduction / fix |
| --- | --- |
| Source installer on a non-default branch | Fresh GitHub clone followed by detached checkout failed. Resolve remote branch/tag/commit to SHA first; exercise the real bootstrap against an isolated Git fixture. |
| Provider-key leakage on redirects | Local HTTP upstream redirected to a second origin and received x-api-key. Block different-origin redirects for both streaming and non-streaming clients; keep same-origin redirects working. |
| Responses tool stream panic | Implicit tool creation failed at the output bound, but its caller indexed an absent item. Propagate that error and account for metadata once. |
| Output item bound | The 4097th item was accepted. Check before allocating a new item. |
| SSE frame memory | Small data lines could accumulate without a total frame bound. Enforce 16 MiB/65536 data lines per event and release retained line storage. |
| Rate-limiter memory | Expiry cleanup alone did not cap admin/client maps. Reject new identities once the bounded map is full; existing identities remain usable. |
| Responses easy messages | Standard string content was rejected. Accept both string and part-array forms and preserve mixed input order. |
| Forced function choice | Responses' flat function-name form was silently ignored. Preserve it and reject unsupported tool-choice shapes. |
| Non-streaming tool completion | Native Responses tool calls were labeled end_turn. Emit tool_use/tool_calls through the canonical conversion. |
| Foreign reasoning summary | Responses summaries received a fabricated Anthropic signature. Leave them unsigned. |
| Stateless Responses storage | Outgoing native Responses relied on the provider's storage default. Explicitly set store=false. |
| Unsupported/empty input | Unknown input parts could disappear; empty requests could reach routing. Return explicit request errors. |
| Incomplete response reason | Content filtering was mislabeled token exhaustion; non-stream encoding omitted incomplete_details and total_tokens. Preserve reason and usage totals. |
| Normal completion | OpenAI stop could become Anthropic max_tokens. Report normal completion when no actual stop-sequence value exists. |
| Gemini tool IDs | Calls in separate SSE chunks reused call_0. Assign unique stream-wide call IDs. |

Added 16 Go regression tests (340 Test* functions in the repository) and a source
bootstrap shell test. The new protocol/memory/key-leak tests were observed failing
before their fixes. Native provider credentials are still not available; this
review remains bounded and does not establish universal API compatibility.

The review verifies source installation on branches/tags/SHAs, regression tests,
full verification/race/fuzz, stress, local runtime, all release target builds and
Linux package upgrade. GitHub CI separately runs Docker build/runtime checks.

Operational changes to note:

- Cross-origin redirects now fail explicitly. Configure the actual final upstream
  endpoint rather than depending on a redirect that would expose credentials.
- New admin identities may receive rate-limit rejection while the 4096-entry map
  is full; entries expire under the existing idle policy.
- Unsupported file/reference input and empty Responses requests are rejected;
  no such request should be mistaken for completed work.
- Use beta.2 artifacts instead of beta.1. The first beta remains an older build,
  not an alternative filename for the corrected executable.

### Integration with the updated main branch

Main advanced by 91 commits during the review. The final beta.2 also incorporates
`ba91c531e13826a7d6637022fb2a805a4e709501`, preserving its hedging cancellation and
attempt-budget fixes, ordered quota observations, Responses health/capability
probes, provider editor improvements and all regression cases. The merged tree
contains 376 Go Test* functions.

Merge-specific test adjustments: use separate names for duplicate close-tracking
fixtures; compare runtime version with the shared build version; assert zero-based
actual output-array indexes for tool-only Responses streams; and commit a content
event before testing a streamed error terminal. Before commitment, protocol errors
remain eligible for failover. No content frame is fabricated to reserve index zero.
The editor test now populates the newly exposed Responses-path input.
